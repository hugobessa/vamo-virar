# @vamo-virar/crypto

The VV1 suite and every protocol envelope ([`docs/protocol.md`](../../docs/protocol.md)
§1.3, §2–§7, §10, §12), in pure TypeScript on `@noble/*` (no WebCrypto, so
it runs in React Native's Hermes).

| Module | What |
|---|---|
| `primitives` | Ed25519 (strict verify), X25519, HKDF-SHA256, XChaCha20-Poly1305, context framing |
| `hpke` | RFC 9180 base mode, single-shot, DHKEM(X25519)/HKDF-SHA256/ChaCha20Poly1305 |
| `keys` | per-community member keys, `community_id` / `member_id` / `mailbox_id`, epoch key derivation, `Keyring` |
| `envelope` | sealing/opening ops, control headers, log entries and the hash chain, `LogVerifier` (device-side §8.2 → domain `Entry`) |
| `keyenv` | key envelopes (K_epoch sealed to a member) |
| `rotation` | `rotateEpoch`: new epoch key, `rotate` control op, key envelopes for the remaining members |
| `snapshot` | encrypted, admin-signed snapshots |
| `intake` | join requests sealed to the intake key, node auth signatures, invite hashes |

Tests (`npm test`):

- **interop**: HPKE against hpke-js in both directions; vectors against the
  Rust crate `crates/vv-crypto`;
- **attacks**: tampering with any envelope field, a member lifting someone's
  signed op into a new envelope, impersonation, forged control headers, key
  envelopes and join requests opened by the wrong party, malleated and
  small-order signatures;
- **end to end** (`test/e2e.test.ts`, with a mock node implementing only the
  node-side checks): join via intake, events, removal and rotation, the
  removed member locked out, a new member bootstrapping from a snapshot,
  200 ops of catch-up, a node rewriting history, and a stolen node database
  searched for names, event text and keys.

`tests/vectors/vv1.json` is generated by `test/vectors.test.ts`; regenerate
only for an intentional wire change:

```sh
VV_WRITE_VECTORS=1 npm run vectors -w @vamo-virar/crypto
```
